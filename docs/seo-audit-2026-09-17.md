# SEO audit and remediation plan

- Date: 2026-09-17
- Site: https://lauramiron.pages.dev/
- Repo age: first commit 2026-09-14, latest commit 2026-09-17 (`git log --reverse --date=short`)
- Method: source review of `D:\Projects\Website` + live HTTP header and response checks through the in-app browser against the production deploy.

## Executive summary

The site is three days old. The whole SEO layer (404, robots, headers, favicons, bilingual static pages, page generator, JSON-LD) landed on 2026-09-17. There is no ranking history and no crawl history yet, so nothing can be judged on performance data.

The technical baseline is unusually good for a new site. Most items an audit normally flags are already correct here (see "Already correct"). The real gaps are few:

1. **F1** Google Search Console is not verified. Nothing else can be measured until it is.
2. **F2** Grade numbers appear only as Roman numerals in indexable text (`Clasa a VI-a`). The Arabic form students type (`clasa a 6-a`) is absent.
3. **F3** Grade pages carry ~100–130 words and an identical meta-description template across all eight grades.
4. **F4** Static assets are served with `max-age=0, must-revalidate`, so nothing caches.
5. **F5** A batch of cheap metadata additions.
6. **F6** Branch preview deployments are indexable. Low risk, one-line fix.
7. **F7** Two rich-result types fit this site exactly (Math solver, Education Q&A) and are unused. Upside, not a defect.

Everything below that is a note, not a defect.

## Findings

### F1 — Search Console is not verified (blocking)

**Issue.** No verification tag and no verification file exist in the repo.

**Impact.** No indexation data, no coverage errors, no query data, no way to submit the sitemap or to confirm Google has crawled anything. Every other recommendation stays unmeasurable.

**Evidence.**
```
grep -rn "google-site-verification\|msvalidate\|yandex-verification" --include=*.html .
(no matches)

ls | grep -i "google\|bing\|yandex"
(no matches)
```

**Fix.** Verify the property in Google Search Console (HTML tag in the `<head>`, emitted by `tools/build_pages.mjs`, or DNS TXT on a future custom domain). Submit `https://lauramiron.pages.dev/sitemap.xml`. Repeat for Bing Webmaster Tools.

**Priority.** P0.

**Note.** Verification may already exist outside the repo (for example a DNS record or a Google Analytics link). Confirm before adding a tag.

### F2 — Grade numbers are Roman-only in all indexable text

**Issue.** Every title, meta description, H1, breadcrumb and JSON-LD `educationalLevel` uses `Clasa a VI-a`. The Arabic form `clasa a 6-a` / `clasa 6` appears nowhere in server-rendered HTML.

**Impact.** Queries typed with digits have no literal match on the page. This is the discriminating on-page signal for a grade-targeted site.

**Evidence.**
- `tools/build_pages.mjs:56` — `return lang === 'en' ? \`Grade ${grade}\` : \`Clasa a ${Catalog.ROMAN[grade]}-a\`;`
- `assets/js/i18n.js:60` — `'seo.grade.title': 'Materiale de matematică pentru {grade} | Laura Miron'`
- Live: `<title>Materiale de matematică pentru Clasa a VI-a | Laura Miron</title>`, `<h1>Clasa a VI-a</h1>`
- The pattern already exists for on-site search only: `assets/js/catalog.js:156` returns `['clasa a VI-a', 'clasa 6', 'grade 6', '6']`. That list is client-side and never reaches the HTML.

**Fix.** Carry both forms in the SEO strings, not in the visible H1 (which stays clean).
- Add a `gradeNumericOf(grade)` helper next to `gradeNameOf` in `tools/build_pages.mjs:55`, returning `clasa a 6-a`.
- Add a second placeholder to the Romanian SEO templates in `assets/js/i18n.js:60-61`, keeping `{grade}` and adding `{gradeNum}`:
  - `'seo.grade.title': 'Matematică {gradeNum} ({grade}): materiale gratuite | Laura Miron'`
  - `'seo.grade.description': 'Materiale de matematică pentru {gradeNum}: teorie, fișe de lucru, teste și jocuri, de prof. Laura Miron.'`
- Add one sentence to `seo.grade.intro` (`assets/js/i18n.js:62`) containing the Arabic form.
- Add both forms to the material-page `keywords` where a grade is named.
- Regenerate with `node tools/build_pages.mjs`.

**English side needs no change.** `gradeNameOf(grade, 'en')` at `tools/build_pages.mjs:56` already returns `Grade 6`, which is the digit form. Only the Romanian templates are affected.

No search-volume figure is quoted here because none was measured. Carrying both forms is safe regardless of the split.

**Priority.** P1.

### F3 — Grade pages are thin and share one description template

**Issue.** A grade page contains only a heading, a templated lead and a list of links. All eight grade descriptions are the same sentence with `{grade}` swapped.

**Impact.** Little unique text to rank on, and near-duplicate meta descriptions across eight URLs.

**Evidence.**
```
sed -n '/<main/,/<\/main>/p' clasa-6.html | sed 's/<[^>]*>/ /g' | wc -w   ->  101
sed -n '/<main/,/<\/main>/p' clasa-9.html | sed 's/<[^>]*>/ /g' | wc -w   ->  130
```
`assets/js/i18n.js:61` — one template for all grades.

Live descriptions:
- `/clasa-6`: "Toate materialele de matematică pentru Clasa a VI-a: teorie, fișe de lucru, teste și jocuri, de prof. Laura Miron."
- `/en/clasa-6`: "All math materials for Grade 6: theory, worksheets, tests and games, by teacher Laura Miron."

**Fix.** Add a per-grade intro of 60–100 words naming the actual chapters of that year (for grade 6: numere naturale, fracții, rapoarte și proporții, unghiuri, triunghiuri). Store it in `data/materials.json` as a `grades` block with `intro.ro` / `intro.en`, render it above the topic list, and use its first sentence as the meta description. It helps students as much as it helps ranking.

**Priority.** P1.

### F4 — No browser caching for static assets

**Issue.** Cloudflare Pages serves every asset with `cache-control: public, max-age=0, must-revalidate`. `_headers` sets no cache rules.

**Impact.** Every repeat visit revalidates CSS, JS, images and PDFs. Extra round trips on each navigation.

**Evidence.** Live `fetch` header read:

| file | cache-control |
|---|---|
| `assets/css/style.css` | `public, max-age=0, must-revalidate` |
| `assets/js/catalog.js` | `public, max-age=0, must-revalidate` |
| `assets/img/og-image.png` | `public, max-age=0, must-revalidate` |
| `favicon.svg` | `public, max-age=0, must-revalidate` |

`tools/build_pages.mjs:704-737` (`renderHeaders`) emits only `X-Robots-Tag` and PDF `Link` rules.

The uniform value across every content type is the Cloudflare Pages default, not a bug. Cloudflare's own headers documentation names `_headers` as the supported way to change it, with this exact example: "Configure custom browser cache behavior … `/static/*` → `Cache-Control: public, max-age=31556952, immutable`" (developers.cloudflare.com/pages/configuration/headers/). So the rule below will stick.

**Fix, step 1 (do now).** Add to `renderHeaders`:
```
/assets/*
  Cache-Control: public, max-age=86400
/materiale/pdf/*
  Cache-Control: public, max-age=86400
```
A one-day TTL is safe without content hashing: an asset edit goes live within a day, and the deploy itself is near-instant for first-time visitors.

**Fix, step 2 (later, optional).** For `max-age=31536000, immutable` the generator must emit content-hashed filenames (`style.a1b2c3.css`) and rewrite every reference. That is a real change to `build_pages.mjs` and the validator. Do not do it today.

**Priority.** P2 for step 1, P4 for step 2.

### F5 — Cheap metadata batch

All small, all safe, all in one pass through `tools/build_pages.mjs`.

| Item | Where | Why |
|---|---|---|
| `<meta name="robots" content="max-image-preview:large, max-snippet:-1, max-video-preview:-1">` on indexable pages | head builder, `tools/build_pages.mjs:114-140` | Allows large image previews and full snippets |
| `og:image:width`, `og:image:height`, `og:image:alt` | next to `tools/build_pages.mjs:139` | Social cards render correctly on first share |
| An `EducationalOrganization` node with `logo` and `url` | home JSON-LD, `tools/build_pages.mjs:262` | Stronger entity signal than the bare `Person` |
| `Person.sameAs` | `tools/build_pages.mjs:41` (`const PROFILES = []`) | Only if public profiles exist (school staff page, YouTube channel). If there are none, there is nothing to do here. |

**Priority.** P2 as a batch.

**Not recommended: `SearchAction` / sitelinks search box.** It is no longer a supported feature. It does not appear in Google's list of supported structured data (developers.google.com/search/docs/appearance/structured-data/search-gallery, last updated 2026-06-15), and its own documentation page now redirects away. Do not add it.

### F6 — Preview deployments are indexable

**Issue.** `AGENTS.md` documents that every non-`main` push gets `https://<branch>.lauramiron.pages.dev/`. Cloudflare also gives each deploy a `<hash>.lauramiron.pages.dev` URL. Nothing marks these as noindex.

**Impact.** Low today, because every page carries an absolute canonical pointing at production, so a crawled preview should fold into the production URL. But a canonical is a hint, not a directive, and previews of half-finished work can surface.

**Evidence.** `_headers` contains no `*.pages.dev` rule. `tools/build_pages.mjs:704-737` emits none.

**Fix.** Add the rule Cloudflare documents for exactly this case, to `renderHeaders`:
```
https://:version.:project.pages.dev/*
  X-Robots-Tag: noindex
```
This matches only the two-label form (`branch.lauramiron.pages.dev`), so production at `lauramiron.pages.dev` stays indexable. **Do not** add the single-label `https://:project.pages.dev/*` variant Cloudflare also shows — that would noindex the live site.

Source: developers.cloudflare.com/pages/configuration/headers/, "Prevent your workers.dev URLs showing in search results".

**Priority.** P2. Group it with task 3.1, same file, same function.

### F7 — Two structured-data types fit this site and are unused

**Issue.** Google supports two rich-result types aimed at exactly this content, and neither is implemented.

| Type | What Google says it does |
|---|---|
| **Math solver** | "Help students, teachers, and others with math problems by adding structured data to indicate the type of math problems and step-by-step walkthroughs for specific math problems." |
| **Education Q&A** | "Education-related questions and answers that help students discover flashcards on Google Search." |

**Impact.** Upside, not a defect. `MathSolver` fits the worked examples in the theory pages. `Quiz` / flashcard markup fits `quiz-recapitulare-clasa-a-v-a` and the exercise lists. Both can put the site into a rich result that generic competitors do not have.

**Evidence.** developers.google.com/search/docs/appearance/structured-data/search-gallery lists both. The site currently emits only `LearningResource`, `BreadcrumbList`, `CollectionPage`, `WebSite` and `Person` (`tools/build_pages.mjs:256-262`, `:468-491`).

**Fix.** Read the two Google guides first, then decide. `Education Q&A` on the quiz page is the smaller job and the better first test. Do not attempt either before Phase 1 and 2 are done.

**Priority.** P3. High ceiling, needs real effort, and needs Search Console in place to tell whether it worked.

## Notes, not defects

### N1 — Internal links take one redirect hop

Every internal `href` is `clasa-6.html`; the canonical is `https://lauramiron.pages.dev/clasa-6`. Cloudflare Pages redirects the `.html` form to the extensionless form.

Evidence: `fetch('.../clasa-6.html')` → `redirected: true`, `finalUrl: https://lauramiron.pages.dev/clasa-6`, `status: 200`. The exact redirect code was not captured: `redirect: 'manual'` in the browser returns `type: "opaqueredirect", status: 0`, which carries no status.

Cost: 31 URLs, one hop each, roughly 40 ms. Signals still consolidate on the canonical.

Cost of fixing: emitting extensionless hrefs breaks `python -m http.server`, which `AGENTS.md` documents as *the* local preview and whose checking steps say to open `materiale/<id>.html`. A small preview server that maps extensionless paths to `.html` would be needed.

**Recommendation: accept the hop.** Revisit only if Search Console later shows crawl-budget pressure, which is unlikely at 31 URLs.

### N2 — `pages.dev` versus a custom domain

`lauramiron.pages.dev` works fine for ranking: `*.pages.dev` is on the Public Suffix List, so the subdomain is treated as its own site rather than inheriting Cloudflare's. This is not a defect.

A custom `.ro` domain is still worth buying for brand, memorability and trust when sharing with students and parents. Migration is ordinary: add the domain to the same Pages project, point `SITE_URL` at it, keep the `pages.dev` deploy live during the transition.

**Priority.** P3, strategic.

### N3 — Performance is fine today

Measured on `/clasa-6`: TTFB 176 ms, DOMContentLoaded 412 ms, load 566 ms. The Google Fonts stylesheet took 99 ms; `style.css` 60 ms (5.5 KB over the wire, Brotli). Self-hosting the fonts and KaTeX would remove two third-party origins and is a genuine improvement, but the numbers do not make it urgent. Do it after F1–F4.

The grade-9 PDF is 735 KB. Worth checking the other PDFs for size, but they are downloads, not page-load blockers.

### N4 — `en/clasa.html` forwarder is missing

`clasa.html` exists at the root as a noindex forwarder for old `clasa.html?c=N` links. There is no `en/clasa.html`. Harmless unless English links of that shape were ever shared. Add it only if such links exist.

### N5 — English pages

The English tree mirrors the Romanian one correctly (`lang="en"`, own titles, own descriptions, reciprocal hreflang). Search demand for Romanian-curriculum maths in English is small, so treat `/en/` as a service to the bilingual school rather than a traffic channel. No change needed.

## Already correct — do not "fix" these

Verified in source and against live headers:

- Empty grade pages (`clasa-5`, `7`, `10`, `12` and their EN mirrors) carry `<meta name="robots" content="noindex, follow">` and drop hreflang. `grep -rn noindex --include=*.html .`
- `cautare.html`, `en/cautare.html`, `clasa.html`, both `404.html` are noindex.
- A missing URL returns a real HTTP **404**, not a soft 200. `/pagina-inexistenta-test` → `status: 404`, `cache-control: no-store`. The English 404 also returns 404 with its own title, "Page not found – Math with Laura Miron".
- PDFs carry a `Link: <...>; rel="canonical"` header pointing at their HTML page, so ranking goes to the page. Verified live on `teorie-numere-reale-modul-parte-intreaga.pdf`.
- `/data/*` returns `x-robots-tag: noindex`. Verified live on `materials.json`.
- hreflang is reciprocal and includes `x-default`, and a pair is emitted only when both language versions are indexable (`tools/build_pages.mjs:854`, `:901`).
- Page content is server-rendered. The catalog, topic lists and "Noutăți" are in the HTML, not JS-injected.
- Sitemap count matches the indexable page count exactly: 16 RO (home + 4 filled grades + 11 materials) + 15 EN (no quiz) = 31 `<loc>` entries. `lastmod` values vary per page (4× 09-13, 6× 09-14, 3× 09-15, 18× 09-17), so they are real, not stamped.
- All 11 material descriptions are inside the 70–160 character rule, in both languages, and all 11 have `keywords`.
- `LearningResource` + `BreadcrumbList` JSON-LD on every material page, `CollectionPage` + `BreadcrumbList` on grade pages, `WebSite` + `Person` on the home page.
- `lang` attribute is correct on the English tree (`lang="en"` on all five sampled files).
- Canonical, `og:*` and hreflang all use absolute `SITE_URL` URLs; everything else is relative.

## Out of scope for this audit

The Bright Data CLI is not installed on this machine (`which bdata` → exit 2), so no live SERP work was possible. Not measured here:

| Question | Right tool |
|---|---|
| Is the site indexed? How many pages? | Google Search Console → Pages report. Or a `site:lauramiron.pages.dev` query by hand |
| Ranking position for a keyword | Search Console → Performance, once data exists |
| Keyword cannibalisation | Search Console → Performance, query/page view |
| Core Web Vitals field data (LCP, INP, CLS from real users) | PageSpeed Insights, CrUX. The numbers in N3 are single lab measurements from this machine, not field data |
| Crawl errors, coverage detail | Search Console → Pages |
| Backlinks, referring domains | Ahrefs, Semrush, or Search Console → Links |
| Search volume for `clasa a 6-a` vs `clasa a VI-a` | Google Keyword Planner, Ahrefs, Semrush |

What was done instead: full source review of the repository, plus live HTTP status, redirect and header checks against the production deploy through the in-app browser.
